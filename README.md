# Telegram-бот электронной очереди

Студенты записываются на сдачу лабораторных и практических. Бот знает расписание
группы (БГУИР), поэтому даты вводить не нужно: выбираешь предмет, и запись идёт на
ближайшую от текущего момента лабу/практику по нему.

## Как работает очередь
- **Регистрация по заявке** при первом `/start`: ФИО → номер группы → подгруппа. Заявку получают
  старосты группы и админы, принимают или отклоняют кнопкой. До принятия записываться нельзя.
  ФИО, группу и подгруппу потом меняет староста/админ.
- **Расписание** берётся из API БГУИР (`iis.bsuir.by`) по номеру группы и обновляется раз в 6 часов.
  Если API недоступен — используется последняя сохранённая копия, а потом файл
  `schedules/<группа>.xlsx` (выгрузка с iis.bsuir.by, сейчас там 513802).
- **Открытие записи** — за 24 часа до начала занятия. За 30 минут до открытия и в момент
  открытия всем из группы (нужной подгруппы) приходит уведомление. Уведомления можно выключить в профиле.
- **Запись**: выбираешь работу (номер) и, по желанию, настрой на сегодня — 🔥 срочно надо сдать /
  ✅ хочу сдать / 🤷 не уверен. До жеребьёвки запись можно изменить.
- **Жеребьёвка** — за час до начала пары очередь выстраивается по правилам. Следующее правило
  смотрится, только если по предыдущему двое равны:
  1. меньший номер работы раньше (отстающие идут вперёд);
  2. настрой: 🔥 → ✅ → 🤷;
  3. кто в прошлый раз по этому предмету стоял дальше от начала, тот раньше;
  4. 🎲 жребий — только при полном совпадении.

  В очереди рядом с фамилией видно, что решило место. Кто записался после жеребьёвки, встаёт в конец.
  Правила — в `ranking.py` (чистая функция, без Telegram и базы).
- Одна запись на человека на занятие; удалить можно только свою.

## Роли и админка (`/admin`)
- **Студент** — записывается в очередь.
- **Староста** (своя группа) — принимает заявки, удаляет записи в очереди, передвигает людей
  после жеребьёвки (они помечаются ✋), правит ФИО, делает рассылку группе, смотрит журнал.
- **Админ** (Telegram ID в `ADMIN_IDS`) — всё то же в любой группе, плюс подгруппа/группа человека,
  назначение старост, исключение из бота и список предметов.

Каждое действие старост и админов пишется в журнал, а тому, кого оно касается, приходит уведомление.

**Предметы** (что сдают, сколько номеров, на ЛР или ПЗ) хранятся в базе и меняются в админке:
`/admin → Предметы → Добавить из расписания`. При первом запуске список берётся из `config.py` (`SUBJECTS`).

## Настройки
Все секреты и параметры задаются переменными окружения (см. `.env.example`).

| Переменная | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от @BotFather, **обязательно** | — |
| `ADMIN_IDS` | Telegram ID админов через запятую. Если пусто — заявки принимаются автоматически | — |
| `DB_PATH` | путь к файлу SQLite (рядом кладётся кэш расписаний) | `data/queue.db` |
| `TIMEZONE` | часовой пояс | `Europe/Minsk` |
| `UNLOCK_BEFORE_HOURS` | за сколько часов до пары открывается запись | `24` |
| `UNLOCK_WARN_MINUTES` | за сколько минут до открытия предупреждать | `30` |
| `SHUFFLE_BEFORE_MINUTES` | за сколько минут до пары жеребьёвка | `60` |
| `SEMESTER_START`, `SEMESTER_END` | границы семестра, нужны только для xlsx | осенний семестр текущего года |

Свой Telegram ID можно узнать, например, у @userinfobot.

## Локальный запуск
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впиши BOT_TOKEN и ADMIN_IDS
python main.py
```

## Тесты
```bash
pip install pytest
python -m pytest
```

## Запуск на сервере (Debian 12/13)
Белый IP, домен и открытые порты не нужны: бот сам ходит в Telegram (polling).
Нужен только выход в интернет до `api.telegram.org` и `iis.bsuir.by`.
Запускать нужно **одну** копию с одним токеном — две будут мешать друг другу.

**Установка** (на сервере):
```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/millirim/queue-bot-fork.git ~/queue-bot
sudo bash ~/queue-bot/deploy/install.sh
```
Скрипт спросит токен бота (проверит его в Telegram) и твой Telegram ID, поставит всё в
`/opt/queue-bot` и запустит бота как службу. После установки `~/queue-bot` можно удалить.

Что делает установка: отдельный пользователь `queuebot` без прав root, окружение `.venv`,
настройки в `/opt/queue-bot/.env` (доступ только у бота), служба systemd с автозапуском и
перезапуском при падении, ежедневный бэкап базы в 4:00 (`/opt/queue-bot/backups`, хранятся 14 дней).

**Команды на каждый день:**
| Что | Команда |
|---|---|
| логи в реальном времени (выход — Ctrl+C) | `journalctl -u queue-bot -f` |
| состояние | `systemctl status queue-bot` |
| перезапуск | `sudo systemctl restart queue-bot` |
| обновить из GitHub | `sudo bash /opt/queue-bot/deploy/update.sh` |
| поменять настройки | `sudo nano /opt/queue-bot/.env`, потом перезапуск |
| бэкап вручную | `sudo systemctl start queue-bot-backup` |

`update.sh` показывает, что нового, делает бэкап, обновляет код и зависимости и перезапускает
бота. Если новая версия не запустилась — сам откатывается на прошлую.

**Восстановить базу из бэкапа:**
```bash
sudo systemctl stop queue-bot
sudo -u queuebot cp /opt/queue-bot/backups/queue-<дата>.db /opt/queue-bot/data/queue.db
sudo rm -f /opt/queue-bot/data/queue.db-wal /opt/queue-bot/data/queue.db-shm
sudo systemctl start queue-bot
```
