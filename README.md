# Telegram-бот живой очереди на сдачу лаб

Бот для одной учебной группы. По каждому предмету есть **живая очередь** — в ней всегда вся
группа. Её открывают прямо на паре и смотрят, кто следующий. Никаких дат и расписаний.

## Как работает очередь
- **Регистрация по заявке**: при первом `/start` вводишь ФИО, заявку принимает староста или админ.
  До принятия бот не пускает. ФИО потом исправляет староста/админ.
- **Порядок** (`ranking.py`):
  1. 🙋 **сверху** — кто нажал «Хочу сдать следующим». Среди них раньше тот, у кого меньше сдано,
     при равенстве — кто раньше поднял руку;
  2. **ниже** — все остальные: у кого меньше сдано, тот выше; при равенстве — по алфавиту.
- **«✅ Сдал»** — счётчик сданных +1, человек остаётся в списке, отметка 🙋 снимается.
  Ошибся — кнопка «−1». Сколько сдано, каждый отмечает сам, честно; староста может поправить.

## Роли и админка (`/admin`)
- **Студент** — смотрит очереди, поднимает руку, отмечает сданные.
- **Староста** — принимает заявки, правит ФИО и сданные, снимает отметку 🙋, делает рассылку,
  смотрит журнал.
- **Админ** (Telegram ID в `ADMIN_IDS`) — всё то же, плюс назначение старост, исключение из бота
  и предметы (название и сколько всего работ).

Каждое действие старост и админов пишется в журнал, а тому, кого оно касается, приходит уведомление.
При первом запуске предметы берутся из `config.py` (`SUBJECTS`), дальше меняются в админке.

## Настройки
Задаются в `.env` (см. `.env.example`).

| Переменная | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от @BotFather, **обязательно** | — |
| `ADMIN_IDS` | Telegram ID админов через запятую. Если пусто — заявки принимаются автоматически | — |
| `DB_PATH` | путь к файлу SQLite | `data/queue.db` |
| `TIMEZONE` | часовой пояс для времени в журнале | `Europe/Minsk` |

Свой Telegram ID можно узнать, например, у @userinfobot.

## Локальный запуск
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впиши BOT_TOKEN и ADMIN_IDS
python main.py
```

## Запуск на сервере (Debian 12/13)
Белый IP, домен и открытые порты не нужны: бот сам ходит в Telegram (polling).
Нужен только выход в интернет до `api.telegram.org`.
Запускать нужно **одну** копию с одним токеном — две будут мешать друг другу.

**Установка** (на сервере):
```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/millirim/queue-bot-fork.git ~/queue-bot
sudo bash ~/queue-bot/deploy/install.sh
```
Скрипт спросит токен бота (проверит его в Telegram) и твой Telegram ID, поставит всё в
`/opt/queue-bot` и запустит бота как службу. После установки `~/queue-bot` можно удалить.

Что делает установка: отдельный пользователь `queuebot` без прав root, окружение `.venv`,
настройки в `/opt/queue-bot/.env` (доступ только у бота), служба systemd с автозапуском и
перезапуском при падении, ежедневный бэкап базы в 4:00 (`/opt/queue-bot/backups`, хранятся 14 дней).

**Команды на каждый день:**
| Что | Команда |
|---|---|
| логи в реальном времени (выход — Ctrl+C) | `journalctl -u queue-bot -f` |
| состояние | `systemctl status queue-bot` |
| перезапуск | `sudo systemctl restart queue-bot` |
| обновить из GitHub | `sudo bash /opt/queue-bot/deploy/update.sh` |
| поменять настройки | `sudo nano /opt/queue-bot/.env`, потом перезапуск |
| бэкап вручную | `sudo systemctl start queue-bot-backup` |

`update.sh` показывает, что нового, делает бэкап, обновляет код и зависимости и перезапускает
бота. Если новая версия не запустилась — сам откатывается на прошлую.

**Восстановить базу из бэкапа:**
```bash
sudo systemctl stop queue-bot
sudo -u queuebot cp /opt/queue-bot/backups/queue-<дата>.db /opt/queue-bot/data/queue.db
sudo rm -f /opt/queue-bot/data/queue.db-wal /opt/queue-bot/data/queue.db-shm
sudo systemctl start queue-bot
```
