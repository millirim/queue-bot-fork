# AGENTS.md — быстрый контекст для нейросетей и новых разработчиков

Telegram-бот «живая очередь на сдачу лаб» для одной учебной группы. Подробности — в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) (читай перед правками базы и очереди). Пользовательское описание — в `README.md`.

## Суть за минуту
- По каждому **предмету** — один постоянный список всей группы (без дат, расписания и отдельных очередей по парам).
- Порядок: сверху те, кто нажал «🙋 Хочу сдать следующее»; меньше сдано — выше; при равенстве — 🎲 жребий
  (один на человека, предмет, номер работы и день; перебросить нельзя); кто не зарегистрирован — внизу.
- Подгруппы 1/2 — только **фильтр просмотра**, порядок не меняют.
- Обмен местами: двое по согласию меняются местами (`ranking.apply_swaps`), места остальных не двигаются; временный, один на каждую работу.
- Меньше сдано = выше, поэтому «−1» себе — только по заявке, которую одобряет староста/админ; «Сдал» можно отменить 60 с.
- Роли: студент → староста (`/moderator`) → админ (`/admin`); создатели 👑 — `CREATOR_IDS` (раньше `ADMIN_IDS`) в настройках сервера.
- Python 3.11+, aiogram 3 (polling), SQLite (aiosqlite). Тексты для людей — по-русски, разметка HTML (`common.esc` для данных).

## Карта файлов
| Файл | Что внутри |
|---|---|
| `main.py` | запуск: логи, база, роутеры (**порядок: `bottom`, `admin`, `handlers`**), команды меню, polling |
| `config.py` | переменные окружения, начальные предметы `SUBJECTS` |
| `db.py` | **вся работа с SQLite**: схема, миграции, запросы, датаклассы. SQL больше нигде |
| `games/` | игры в ОТДЕЛЬНОМ процессе (служба `queue-bot-games`); файлы с правилами — чистый Python, см. `docs/GAMES.md` |
| `replication.py` | копии базы на другие серверы (шифрование, подпись, отправка); приёмник — `deploy/receiver/` |
| `metrics.py` | нагрузка и события в реальном времени (страница «Live»): кольцо событий, счётчики, WebSocket-источник |
| `features.py` | реестр дополнительных функций, которые админ включает по ролям (`feature_flags`) |
| `ranking.py` | порядок очереди `order()`, жребий `draw_lot()`; чистые функции |
| `bottom.py` | кнопка «На главную» под полем ввода (постоянная клавиатура); роутер подключается **первым** |
| `handlers.py` | студенческая часть: регистрация, очередь, «Сдал/Отменить/−1», «Моё» |
| `admin.py` | панели: заявки, люди, подгруппы, сданные, рассылка, журнал, предметы, копия базы |
| `common.py` | права, отправка, форматирование, команды меню по ролям, кулдаун «Обновить» |
| `logsink.py` | серверные логи в базу (`server_log`), токен вырезается |
| `web.py` | веб-панель (aiohttp в процессе бота): вход по ссылке из `/web`, JSON-API с правами на каждом запросе |
| `webui/` | интерфейс веб-панели: `index.html`, `assets/app.js` (без сборки и библиотек), `assets/app.css` (3 темы; на телефоне таблицы — через `rt()`, без горизонтальной прокрутки) |
| `broadcast.py` | рассылка с форматированием: копия сообщения из бота или HTML и картинки из веба |
| `updater.py` | кнопка «Обновить бота»: запрос → systemd от root → итог админу в чат |
| `deploy/` | установка на Debian, команда `queue-bot`, systemd, бэкапы, дежурный ответчик на время перезапуска (`maintenance.py`) |
| `tests/` | pytest + сквозной сценарий на поддельном Telegram (`harness.py`) |

## Команды
```bash
pip install -r requirements.txt pytest
python -m pytest                 # все тесты, токен и сеть не нужны
python -m pyflakes *.py tests/*.py   # линтер (по желанию: pip install pyflakes)
BOT_TOKEN=... CREATOR_IDS=<твой id> python main.py   # запуск (нужен токен тестового бота)
```

## Правила, которые легко нарушить
1. **База:** SQL только в `db.py`. Новая колонка = строка в `SCHEMA` **и** в `Database._add_new_columns` (для уже
   существующих баз); разовое преобразование данных = ключ в таблице `meta`. **Не увеличивай `SCHEMA_VERSION`** без
   миграции данных — при несовпадении версий база будет стёрта.
2. **Права проверяются на сервере:** каждый обработчик в `admin.py` начинается с `need_staff(...)`
   (`admin_only=True` — только админы). Спрятать кнопку недостаточно.
3. **Не нарушай «меньше сдано = выше»:** любой новый способ уменьшить свой счётчик должен идти через заявку.
4. **HTML:** всё, что приходит от людей или из базы, оборачивай в `esc()`. В журнал (`audit`) пиши чистый текст без тегов.
5. Кнопки: `common.btn(text, data, style=None)`; цвет (`danger`/`success`/`primary`) — по Bot API 9.4. «На главную» — одна общая `common.MENU_BTN`. `callback_data` ≤ 64 байта. Новая кнопка → строка в таблице кнопок `docs/ARCHITECTURE.md` (раздел 8) — `tests/test_docs.py` это проверяет.
6. **Дополнительная функция** (не очередь): запись в `features.FEATURES`, проверка `feature_allowed` в боте и `need(..., feature=)` в вебе.
7. Новый обработчик студента ставь **выше** запасных (`stale_callback`, `fallback_message`) в конце `handlers.py`.
7. Секреты: токен бота — только в `/etc/queue-bot/env`; список группы и сданные — только в базе, **не в репозитории**.
   Токен не должен попасть в логи (`logsink.SECRET` вырезает его, не ломай).
8. Время — локальное без tzinfo (`db.local_now()`), все ключи времени строкой ISO.
9. Веб-панель (`web.py`) — второй вход в те же действия: каждое API начинается с `need(request, роль)`, повторяет
   проверки и тексты уведомлений из `admin.py`/`handlers.py`, пишет в журнал через `journal()` (пометка «· веб»).
   Меняешь правило в боте — поменяй и там. Данные в `app.js` вставляются только как текст (`h()`), без `innerHTML`.
10. Состояния FSM хранятся в памяти и сбрасываются при перезапуске — не клади в них то, что нельзя потерять.

## Как проверить свою правку
- Логику очереди — `tests/test_ranking.py`, `tests/test_db.py`.
- То, что видит пользователь (тексты, кнопки, уведомления, права) — **`tests/test_scenario.py`**: длинный сценарий,
  каждая проверка названа по смыслу. Для новой кнопки добавь шаги туда или собери короткий сценарий через `Harness`
  (`h.text(dp, chat_id, "/start")`, `h.press(dp, chat_id, "callback")`, `h.last(chat_id)`, `h.buttons(...)`).
- Настоящего Telegram в тестах нет; перед выкладкой стоит один раз проверить на тестовом боте.

## Развёртывание и релизы
- Работа ведётся в ветке, правка уходит через pull request в `main`; сервер обновляется командой `sudo queue-bot update`
  (код `/opt/queue-bot`, настройки `/etc/queue-bot/env`, база `/var/lib/queue-bot`).
- Миграции базы запускаются сами при старте бота; обновление делает бэкап и откатывается, если бот не поднялся.
- Коммиты — по-русски, коротко: что изменилось и зачем.
