# Переписывание интерфейса веб-панели: задание и контекст

Документ для того, кто будет делать новый интерфейс (в том числе новая сессия Claude): что есть, чего хотят, что нельзя ломать и как проверять.

## Зачем
Отзыв одногруппника: «UI/UX хунта, очень заебно там разбираться, сделай нормальный интерфейс», потом: «сделай проще, буквально минимум текста и минимум интерфейса».
Владелец согласен: интерфейс перегружен и непонятен. Нужно **полностью переписать клиентскую часть** (`webui/`) и сделать её красивой.
Серверную часть (API, права, база, игры) не трогаем без причины.

## Снимок «до»
- Ветка `snapshot-before-ui-rewrite` на GitHub (коммит `dae03c6`, это `main` перед началом работы): старый интерфейс целиком, откат и сравнение — `git diff snapshot-before-ui-rewrite -- webui`.
- Скриншоты старого вида: `docs/screens/*.png` (вымышленные данные).
- Рабочая ветка для переписывания: `ui-rewrite` (от `main`). Результат вливать в `main` частями через PR (squash), каждая часть — рабочая и с зелёными тестами.

## Принципы нового интерфейса
1. **Один главный экран у каждой роли.** Студент открыл панель — сразу видит своё место в очереди и одну главную кнопку («Хочу сдать» / «Сдал»). Всё остальное — на втором плане.
2. **Минимум текста.** Нет абзацев-объяснений на экранах: подсказка — короткая метка или значок «?», правила — отдельная страница «Как это работает». Подписи кнопок — одно-два слова.
3. **Минимум элементов.** Не больше одного основного действия на экран, редкие действия убраны в меню «…» или на второй уровень. Меньше рамок и карточек, больше воздуха.
4. **Студенту — только студенческое.** Админские и серверные разделы (Люди, Заявки, Рассылка, Журнал, Предметы, Live, Сервер) не видны и не занимают место в меню; староста и админ получают их отдельным входом («Управление»).
5. **Телефон важнее ПК.** Большинство открывает панель в Telegram. Сначала проектируем 390 px, потом растягиваем. Нижняя панель вкладок на телефоне, крупные цели для пальца (минимум 44 px).
6. **Красиво и спокойно.** Единая сетка и ритм отступов, один акцентный цвет, мягкие тени без избытка, аккуратная типографика, три темы (светлая, тёмная, AMOLED) и «как в системе» (в Telegram — как в Telegram), уважение `prefers-reduced-motion`.
7. **Быстро.** Без сборки и тяжёлых библиотек; начальная загрузка не больше нескольких сотен КБ; обновление данных без перерисовки всей страницы.

## Жёсткие ограничения (не обсуждаются)
- **CSP**: `default-src 'self'; style-src 'self'; script-src 'self'; img-src 'self' data: blob:; connect-src 'self'` (см. `web.py: SECURITY_HEADERS`). Значит: никаких `style="..."` в разметке и `innerHTML` с данными, никаких CDN, внешних шрифтов и скриптов. `el.style.x = ...` через JS разрешён, ES-модули (`<script type="module" src="/assets/...">`) тоже.
- **Без шага сборки** (npm, бандлеры): файлы отдаются как есть из `webui/` (`web.py` → `/assets/`). Можно разбить код на ES-модули.
- Шрифты — только свои файлы в `webui/assets/fonts` (сейчас Exo 2 для ника создателя; лицензия SIL OFL).
- **Мини-приложение Telegram**: `#tgWebAppData` в адресе, события через `TelegramWebviewProxy`/`postMessage`, свой разбор темы и безопасных зон; SDK telegram.org не подключаем (см. `app.js: tg`, `setupTelegram`, `docs/ARCHITECTURE.md` раздел 14). Приглашение за игровой стол приходит как `/?room=КОД` → `#/games/КОД`.
- Работает без белого IP через прокси: относительные адреса, WebSocket по `location.host`.
- Доступность: фокус виден, кнопки доступны с клавиатуры, контраст не ниже 4.5:1 на всех темах.
- Настоящих людей на скриншотах и в тестовых данных быть не должно — только вымышленные (стенд `tools/ui_preview`).

## Что менять нельзя (контракты)
**Серверный API** (`web.py`, ответ и права проверяет сервер): `GET /api/me`, `/api/overview`, `/api/my`, `/api/badges`, `/api/subjects`, `/api/queue/{id}` (+ `POST …/want|done|undo|minus|swap`),
`/api/swaps/{id}/accept|end|cancel`, `/api/progress/{sid}/{pid}`, `/api/requests` (+ `POST …/reg/{chat}`, `…/minus/{id}`), `/api/people` (+ карточка и действия), `/api/subgroups`,
`/api/broadcast`, `/api/journal`, `/api/polls…`, `/api/suggestions…`, `/api/features`, `/api/server`, `/api/replication`, `/api/live` (WebSocket), `/api/metrics`, `/api/presence`, `/api/ping`,
`/api/games/status|people|invite|ws`, `/api/login`, `/api/logout`. Все изменяющие запросы шлют заголовок `X-Queue-Bot: 1`; админ может смотреть «глазами» роли заголовком `X-View-As`.
Поля, по которым интерфейс скрывает пункты: `/api/me` → `role`, `view`, `views`, `creator`, `features{ключ: bool}`, `student`.
**Игры**: каждая игра регистрируется `window.QB_GAMES.register(kind, {title, icon, solo, render(root, api)})` (контракт — `docs/GAMES.md`); `webui/assets/games/shell.js` — лобби и соединение. Экраны игр можно перерисовать,
но контракт `render(root, api)`, формат записей и поведение сервера не менять. `window.QB_APP` (помощники для игр) оставить или заменить с обновлением `shell.js`.
**Тесты, которые касаются интерфейса**: `tests/test_web.py`, `test_features.py`, `test_presence.py`, `test_metrics.py`, `test_games_proxy.py` проверяют API, а не вёрстку; вёрстку проверяем скриншотами и руками (ниже).

## Что есть сейчас (`webui/`, ~6 тыс. строк)
`index.html`, `assets/app.js` (2091 строк, всё в одном файле: каркас, экраны, помощники), `assets/app.css` (687), `assets/theme.js` (тема до отрисовки), `assets/games/*` (оболочка и 6 игр), шрифты, `mark.svg`.
Токены дизайна — CSS-переменные в `:root` (`--bg --surface --text --border --brand #ff4801 --ok --warn --bad --info --radius --sidebar --top --statusbar --tabbar …`), темы через `data-theme`.
Экраны (`PAGES` в `app.js`) и кому доступны:
| Экран | Кто | Что делает |
|---|---|---|
| Обзор `overview` | все | плитки (люди, заявки, «хотят сдать»), мои места по предметам, голосования, обмены, последние действия (старосте) |
| Очереди `queues`, очередь `queue` | все | список предметов; очередь предмета, «Хочу сдать» / «Сдал» / «Попросить −1» / обмен местами, фильтр подгрупп; староста правит сданные |
| Моё `my` | студент | сданные по предметам, место, обмены |
| Игры `games` | все (функция) | лобби, столы, одиночные игры, рекорды |
| Голосования `polls` | все (функция) | голосовать; админ создаёт/закрывает |
| Предложения `suggestions` | все (функция) | идеи по боту, ответы старост |
| Как это работает `rules` | все | правила очереди |
| Заявки `requests`, Люди `people`, Рассылка `broadcast`, Журнал `journal` | староста+ | заявки на вход и −1; список группы и карточка человека; рассылка с форматированием; журнал действий |
| Предметы `subjects`, Live `live`, Сервер `server` | админ | предметы; нагрузка и события в реальном времени; обновление бота, копия базы, копии на другие серверы, функции по ролям, сессии |
Вокруг: верхняя панель (поиск, переключатель «смотреть как», аккаунт), строка связи внизу (пинг, время сервера, аптайм), на телефоне нижние вкладки, ящик карточки человека, диалоги, всплывающие подсказки, тосты, цветные ники ролей (`nick()`), точка «онлайн».

## Подсказки по упрощению (обсуждаемо)
- Меню студента: **Очередь · Игры · Ещё** (голосования, предложения, правила — в «Ещё»). Меню старосты/админа: то же плюс «Управление» (Заявки, Люди, Рассылка, Журнал; у админа ещё Предметы и «Система» = Сервер + Live).
- Экран «Обзор» студента = «мои очереди»: список предметов с моим местом и кнопкой; плитки статистики — только в «Управлении».
- Очередь: сверху «твоё место», одна большая кнопка по ситуации; остальной список компактный, правка людей — по нажатию.
- Строка связи внизу (пинг, джиттер, расхождение часов) — только админу и свёрнутой; студенту не нужна.
- Все длинные пояснения заменить короткими подписями; правила — на странице «Как это работает».
- Игры: лобби в виде крупных плиток; настройки стола спрятать за «Создать» с разумными умолчаниями.

## План работ (предложение)
1. **Основа.** Токены (цвета, типографика, отступы, радиусы, тени), каркас (меню по ролям, верхняя панель, нижние вкладки, тема, мини-приложение), помощники интерфейса (кнопки, список, диалог, тост), разбиение `app.js` на модули. Результат: пустой каркас с настоящими меню и темами.
2. **Студент.** Очереди, «Моё», обмен, голосования, предложения, правила. Проверить на 390 px и ПК, во всех темах.
3. **Староста.** Заявки, Люди (список и карточка), Рассылка, Журнал.
4. **Админ.** Предметы, Сервер (обновление, копии, функции), Live.
5. **Игры.** Лобби и оболочка в новом стиле, затем экраны игр по очереди.
6. **Доводка.** Анимации (с `prefers-reduced-motion`), пустые и ошибочные состояния, доступность, быстродействие, новые скриншоты для README (`docs/screens`), обновление `docs/ARCHITECTURE.md` (раздел 14) и `README.md`.
После каждого шага: PR в `main` (squash), зелёные тесты, скриншоты «до/после» в описании PR.

## Как смотреть результат
Стенд на вымышленных данных (настоящая панель, 14 человек, прогресс, голосование, предложения):
```bash
python tools/ui_preview/seed_server.py /tmp/ui 1200 &        # панель на http://127.0.0.1:8099, токены входа лежат в /tmp/ui
NODE_PATH=$(npm root -g) NO_PROXY=127.0.0.1 node tools/ui_preview/shots.js /tmp/ui /tmp/ui overview queue people   # скриншоты ПК (светлая) и телефона (тёмная)
```
Токены входа одноразовые: для нового входа перезапусти стенд. Войти вручную: `http://127.0.0.1:8099/api/login` не открывается из адресной строки (нужен POST с `X-Queue-Bot: 1`),
поэтому удобнее скриптом Playwright (Chromium и Playwright для Node установлены; параметров запуска не нужно; `NO_PROXY=127.0.0.1` обязателен в среде с прокси).
Роли стенда: `ta`, `tb`, `tc` — создатель; `tf` — староста; `tg` — админ; `td`, `te` — обычный студент. Скриншоты обязательно смотреть глазами (на 390 и 1280 px, в светлой, тёмной и AMOLED).
Проверка перед PR: `python -m pytest -q`, `python -m pyflakes *.py games tests tools`, `node --check` для каждого `.js`, отсутствие ошибок в консоли браузера и нарушений CSP.

## Правила работы
- Коммиты от `millirim <197052855+millirim@users.noreply.github.com>`, по-русски, коротко, без эмодзи; в конце строки `Co-Authored-By: Claude …` и `Claude-Session: …`, как в прошлых коммитах.
- Документация обновляется вместе с кодом (`docs/ARCHITECTURE.md`, `AGENTS.md`, `README.md`); `tests/test_docs.py` следит за картой файлов и кнопками бота.
- Не добавлять в репозиторий настоящие фамилии, токены, список группы.
- Серверные запросы и права не менять ради интерфейса: если нужен новый ответ API, сначала тест в `tests/test_web.py`.
