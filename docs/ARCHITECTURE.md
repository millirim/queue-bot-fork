# Устройство бота: движок и база данных

Подробное и точное описание. Короткая версия для быстрого старта — в [`AGENTS.md`](../AGENTS.md).
Если меняешь код, меняй и этот файл: тест `tests/test_docs.py` проверяет, что все таблицы базы,
переменные окружения и callback-кнопки здесь упомянуты.

## 1. Что это

Telegram-бот «живая очередь на сдачу лаб» для **одной учебной группы** (~30 человек). Нет дат, расписания и
отдельных очередей по парам: по каждому **предмету** есть один постоянный список всей группы. Его открывают на паре
и смотрят, кто следующий. Порядок строится по числу сданных работ и отметке «хочу сдать следующее»
(правила — в разделе 5).

- Стек: Python 3.11+ (на сервере 3.13), aiogram 3.31 (long polling, без вебхуков), aiosqlite (SQLite, один файл).
- Один процесс, одна копия на токен. Белый IP и открытые порты не нужны.
- Весь текст для пользователей — на русском, разметка Telegram — HTML (`parse_mode=HTML`), поэтому всё, что
  вставляется в текст из данных, проходит через `common.esc()`.

## 2. Карта файлов

| Файл | Роль |
|---|---|
| `main.py` | Точка входа: логи, база, `Dispatcher`, команды меню, polling. Порядок — раздел 3. |
| `config.py` | Настройки из переменных окружения и начальный список предметов `SUBJECTS`. |
| `db.py` | **Вся работа с SQLite.** Схема, миграции, все запросы, датаклассы (`Student`, `Subject`, `Row`, `Standing`, …). SQL нигде больше не пишется. |
| `ranking.py` | Чистая функция порядка очереди `order()`, `draw_lot()`, текст правил `RULES`. Без Telegram и базы. |
| `handlers.py` | Роутер студента: регистрация, очередь, «Сдал/Отменить/−1», «Моё», `/start /help /my /cancel`, запасные обработчики. |
| `admin.py` | Роутер Панели Админа (`/admin`) и панели старосты (`/moderator`): заявки, люди, подгруппы, сданные, рассылка, журнал, предметы, копия базы. |
| `common.py` | Общее: права (`is_owner/is_admin/is_staff`), отправка (`show`, `send`, `send_many`, `edit_sent`), форматирование (`esc`, `kb`, `btn`, `queue_text`, `short_name`), команды меню по ролям, кулдаун «Обновить», фильтр подгруппы. |
| `logsink.py` | Серверные логи в таблицу `server_log` (хендлер `logging` + фоновая задача). |
| `deploy/` | Установка и обслуживание на сервере (раздел 11). |
| `tests/` | pytest (раздел 12). |

Зависимости импорта (стрелка — «импортирует»): `main → admin, handlers, common, db, logsink, config`;
`handlers → admin (close_notices, notify_*), common, db, ranking`; `admin → common, db, logsink, ranking, config`;
`common → db, ranking, config`; `db → ranking, config`; `logsink → db, config`. Циклов нет (`ranking` и `config`
ни от кого не зависят).

## 3. Запуск (`main.py`)

1. `logging.basicConfig(INFO)` и `logsink.install()` — те же логи пишутся и в базу.
2. Проверка `BOT_TOKEN`; если `ADMIN_IDS` пуст — предупреждение (заявки тогда принимаются автоматически).
3. `Database.connect()` (раздел 4.3), запуск фоновой задачи `logsink.flusher`.
4. `Dispatcher`, `dp["db"] = db` (хендлеры получают `db: Database` аргументом).
5. **Порядок роутеров важен:** сначала `admin.router`, потом `handlers.router` — в конце `handlers.py` стоят
   «запасные» обработчики (`stale_callback`, `fallback_message`), которые ловят всё подряд.
6. Команды меню: всем `BASE_COMMANDS`; админам (`ADMIN_IDS` и назначенным) добавляется `/admin`, старостам `/moderator`
   (`set_commands` с `BotCommandScopeChat`).
7. `start_polling`. При остановке: запись «Бот остановлен», сброс последних логов, закрытие базы.

FSM-состояния (`aiogram` `MemoryStorage`, **сбрасываются при перезапуске**): `handlers.MinusForm.reason`;
`admin.AdminForm`: `name`, `roster`, `subgroup_list`, `broadcast`, `subject_name`, `subject_emoji`, `subject_total`.

## 4. База данных

### 4.1. Общее

SQLite, один файл (`DB_PATH`; на сервере `/var/lib/queue-bot/queue.db`), WAL, `foreign_keys=ON`. Одно соединение
`aiosqlite` на весь процесс (`Database.conn`); каждая запись сразу `commit`. Время — **локальное, без tzinfo**,
строкой ISO (`TIMEZONE`, по умолчанию Europe/Minsk): `db.local_now()`.

### 4.2. Таблицы

**`students`** — список группы. Главная таблица: очередь строится по ней.
| Колонка | Смысл |
|---|---|
| `id` | PK. Все связи идут по нему, а не по Telegram ID. |
| `name` | ФИО полностью, `UNIQUE`. В очереди показывается как «Фамилия И.О.» (`common.short_name`). |
| `active` | 1 — в группе, 0 — убран (например, отчислен). Убранных нет в очередях, данные сохраняются. |
| `chat_id` | Telegram ID привязанного аккаунта, `UNIQUE`; `NULL` — человек ещё не зарегистрировался в боте. |
| `username` | @ник на момент привязки (только для показа админам). |
| `role` | `user` / `starosta` / `admin`. Роль **закреплена за ФИО**: её можно назначить заранее, и она сработает после регистрации; при отвязке Telegram роль остаётся. |
| `subgroup` | 1, 2 или 0 (не указана). **Только фильтр просмотра**, на порядок очереди не влияет. |

**`requests`** — заявки на вход: «этот Telegram — вот этот человек из списка». PK `chat_id` (одна заявка на аккаунт),
`student_id → students ON DELETE CASCADE`, `username`, `created_at`.

**`subjects`** — предметы: `id`, `name` `UNIQUE`, `total` (сколько всего работ), `emoji` (по умолчанию `📚`).
`Subject.title` = «эмодзи название» — так предмет показывается в кнопках и заголовках.

**`progress`** — сколько сдал человек по предмету. Ключ — пара `student_id` + `subject_id` (оба → `students` и
`subjects`, `ON DELETE CASCADE`).
| Колонка | Смысл |
|---|---|
| `done` | Сдано работ, `0…subjects.total`. |
| `want_since` | Время нажатия «Хочу сдать следующее»; `NULL` — не хочет. Используется только как флаг «хочет». |
| `lot` | **Устарела**, не используется (жребий теперь в `lots`); колонка осталась ради старых баз. |
| `undo_until` / `undo_want` | До какого времени можно отменить своё «Сдал» (60 с) и какая отметка «хочу сдать» была до него. |

Строки `progress` создаются лениво (`_ensure_progress`); нет строки — значит `done = 0`, не хочет.

**`lots`** — жребий. Колонки `student_id`, `subject_id`, `work` (номер работы, `done + 1`), `day` (местная дата),
`lot` (само число); PK — первые четыре, то есть **одно число на человека, предмет, номер работы и день**. Создаётся при первом показе очереди, когда человек «хочет» (`Database._lots`,
`INSERT OR IGNORE`), поэтому никакие нажатия его не меняют. Записи прошлых дней удаляются — в полночь у всех
новый жребий. `lot` — случайное число от 0 до 2⁶²−1 (`ranking.draw_lot`, `random.SystemRandom`).

**`minus_requests`** — заявки «уменьшить сданные на 1» с причиной: `id`, `student_id`, `subject_id`, `reason`,
`created_at`, `UNIQUE (student_id, subject_id)` (новая заявка заменяет старую).

**`request_notices`** — какие сообщения с кнопками бот отправил проверяющим, чтобы после решения у всех заменить
их на итог без кнопок. `applicant` — `chat_id` подавшего заявку (для `kind='reg'`) или `id` заявки на −1
(`kind='minus'`); `reviewer` — кому отправлено; `message_id`; `kind`.

**`audit`** — журнал действий старост и админов: `id`, `at`, `actor_id`, `actor_name` (в виде «админ Иванов Иван»),
`text` (чистый текст, без HTML). Пишется `Database.log_action` через `admin.journal_add`. Не очищается.

**`server_log`** — серверные логи: `id`, `at`, `level`, `logger`, `message`, `trace` (traceback, если был). Хранятся
последние `db.LOG_KEEP` = 5000 строк (лишние удаляются при каждой записи).

**`meta`** — разовые миграции данных: `key`/`value`. Сейчас один ключ `subjects-v2` (прежние названия БЖЧ →
БЖЧ-ЛР/БЖЧ-ПЗ и эмодзи по умолчанию; выполняется ровно один раз на базу).

### 4.3. Создание и миграции (`Database.connect`)

1. `PRAGMA journal_mode=WAL`.
2. `_drop_old_schema` — **только для очень старых баз** (`PRAGMA user_version` меньше `SCHEMA_VERSION`, и есть таблицы
   прошлых поколений): пересоздаёт всё. Сейчас `SCHEMA_VERSION = 4`.
   **Не увеличивай `SCHEMA_VERSION`, не написав миграцию данных: при несовпадении база будет стёрта.**
3. `PRAGMA foreign_keys=ON`, `executescript(SCHEMA)` — `CREATE TABLE IF NOT EXISTS` для всех таблиц.
4. `_add_new_columns` — **так добавляются новые колонки в существующие базы**: `_add_column(table, column, ddl)`
   делает `ALTER TABLE ADD COLUMN`, если колонки ещё нет. Данные не затрагиваются. Затем `_migrate_subjects`.
5. `_seed_subjects` — если таблица `subjects` пуста, заполняет её из `config.SUBJECTS` (название → (число работ, эмодзи)).

Правило для будущих изменений: новая колонка = строка в `SCHEMA` **и** строка в `_add_new_columns`; новая таблица =
только в `SCHEMA`; разовое преобразование данных = ключ в `meta`.

### 4.4. Что делает `Database` (по группам)

- Список: `students`, `get_student`, `student_by_chat`, `free_students`, `add_students`, `rename_student`, `set_active`,
  `unlink` (роль остаётся), `set_role`, `set_subgroup`, `set_subgroups`, `staff_chats`, `member_chats`.
- Заявки на вход: `create_request`, `get_request`, `pending_requests`, `link`, `approve`, `reject`,
  `add_notice`, `pop_notices`.
- Предметы: `subjects` (по алфавиту), `get_subject`, `add_subject`, `rename_subject`, `set_subject_emoji`,
  `set_subject_total`, `delete_subject`.
- Очередь: `queue(subject_id)` → список `ranking.Row` в порядке очереди; `standing` (место в общей очереди и в подгруппе),
  `get_row`; `set_want`, `change_done` (правка счётчика: староста/админ и одобренный −1), `mark_done` («Сдал» самого
  человека), `undo_until`, `undo_done`.
- Заявки на −1: `create_minus`, `get_minus`, `pending_minus`, `delete_minus`.
- Журналы: `log_action`, `journal`, `journal_page`; `add_server_logs`, `server_logs`, `last_error_trace`.
- Копия: `backup_zip` (`VACUUM INTO` во временный файл → zip).
- `parse_roster(text)` — вставленный список ФИО → список имён (пропускает номера, заголовок «№ Фамилия Имя Отчество»,
  пустые строки и строки со словом «отчислен»).

## 5. Порядок очереди (`ranking.py`)

`db.queue()` собирает по `students` (только `active = 1`) строки `Row(student_id, name, done, wants, lot, in_bot, subgroup)`
и сортирует `ranking.order()` по ключу:

1. **Желающие** (`wants`) выше всех остальных.
2. Среди **не желающих** — те, кто **ещё не в боте** (`in_bot = False`, нет `chat_id`), в самом низу, без приоритета.
   (Если староста поставил такому 🙋 — он среди желающих.)
3. Меньше `done` — выше.
4. Среди желающих при равном `done` — меньший `lot` (жребий).
5. По алфавиту (`casefold`).

Подгруппы порядок не меняют: фильтр «Все / 1 подгр. / 2 подгр.» только скрывает чужую подгруппу при показе
(`common.queue_text(..., subgroup=N)`; номера считаются внутри выбранной). Выбор фильтра запоминается на человека в
памяти (`common.subgroup_view`) до перезапуска.

Жребий (раздел 4.2, `lots`) даёт каждому из равных одинаковый шанс на любое место; перебросить его нельзя ни «опустить
и поднять руку», ни «Сдал» → «Отменить». В полночь у всех новый. Равномерность проверена в `tests/test_ranking.py`.

**Нельзя выгодно уменьшить свой счётчик** — меньше сдано значит выше в очереди. Поэтому:
- «✅ Сдал» (+1) доступен всем себе; кнопка «↩️ Отменить» живёт `db.UNDO_SECONDS` = 60 с и возвращает всё как было;
- «−1» себе — только через заявку («🙏 Попросить −1» с причиной), её одобряет другой староста или админ;
  свою заявку решить нельзя; староста/админ себе «−1» напрямую тоже не ставит (`cb_progress_change`);
- староста и админ правят сданные **другим** сразу (с записью в журнал и уведомлением человеку).

## 6. Роли и права

| Роль | Откуда | Что может |
|---|---|---|
| студент (`user`) | по умолчанию | очередь, 🙋, «Сдал», «Отменить», «Попросить −1», «Моё» |
| староста (`starosta`) | `students.role` | + `/moderator`: заявки, ФИО, сданные и 🙋 за других, рассылка, журнал действий |
| админ (`admin`) | `students.role` | + `/admin`: список группы, подгруппы, роли, отвязка Telegram, убрать/вернуть, предметы, серверные логи, копия базы |
| главный админ | `config.ADMIN_IDS` | как админ, **плюс** его нельзя снять из бота; может работать, даже не выбрав себя из списка |

Функции (`common.py`): `is_owner(chat_id)` — в `ADMIN_IDS`; `is_admin(chat_id, student)` — владелец или `student.admin`;
`is_staff` — админ или староста; `staff_kind` → `'admin'` / `'moderator'` / `None`; `panel_name(kind)` — «Панель Админа»
или «Панель старосты». В `admin.py` каждый обработчик начинается с `need_staff(target, db, admin_only=False)`;
`admin_only=True` пускает только админов. Проверка прав всегда на сервере, прятать кнопку недостаточно.

Значки в списке людей: ✅ студент · ✳️ староста · ❇️ админ · ❎ не зарегистрирован (❎✳️ — роль назначена заранее).

## 7. Основные сценарии

**Регистрация.** `/start` без привязки → `show_roster` (свободные имена, `students.chat_id IS NULL`) → «Это я» →
`create_request` + `notify_reviewers` (всем из `ADMIN_IDS` и `staff_chats()`; сообщения запоминаются в `request_notices`).
Проверяющий жмёт ✅/❌ → `db.approve`/`reject` → `close_notices` меняет сообщение у **всех** проверяющих на итог без кнопок.
Одно имя — один аккаунт (`link` отказывает, если имя уже занято). Если `ADMIN_IDS` пуст или пишет главный админ —
привязка сразу, без заявки. Если имя с ролью — проверяющего предупреждают.

**«Сдал».** `mark_done` → `change_done(+1)`: счётчик +1, отметка 🙋 снимается; запоминает `undo_until` и прежний `want_since`.
`undo_done` в течение минуты возвращает счётчик и отметку.

**«−1» по заявке.** `sm:` → FSM `MinusForm.reason` → `create_minus` → `notify_minus` (всем проверяющим, кроме просящего) →
`mr:ok|no` → `change_done(−1)`, ответ человеку, запись в журнал, `close_notices(kind='minus')`.

**«Обновить».** `common.refresh_wait(chat_id)` — 3 секунды на человека (память процесса); в тексте — время обновления.
`show()` терпит `message is not modified` и `TelegramRetryAfter`.

**Команды меню** (`common.set_commands`) пересоздаются при смене роли, принятии заявки, отвязке, возврате/удалении из группы
и при старте бота.

## 8. Кнопки (`callback_data`)

Лимит Telegram на `callback_data` — 64 байта. Префиксы короткие, поля через `:`. «ID» — `students.id`, `subjects.id` или
`chat_id` (где указано). Все обработчики ловятся в `handlers.py` (студент) и `admin.py` (панели); у `admin.py`
приоритет.

**Студент (`handlers.py`):**
| Префикс | Значение |
|---|---|
| `menu`, `help`, `my` (и старый `profile`) | главное меню, «Как это работает», «Моё» |
| `reg`, `reg:again`, `rg`, `rgok`, `rg:none` | регистрация: список имён, выбор `rg:<student_id>`, подтверждение `rgok:<student_id>`, «меня нет в списке» |
| `s:<subject_id>` | открыть очередь |
| `sr:<subject_id>` | «Обновить» (с кулдауном) |
| `sf:<subject_id>:<0/1/2>` | фильтр подгруппы |
| `sw:<subject_id>:<0/1>` | «Хочу сдать следующее» / «Передумал» |
| `sd:<subject_id>:1` | «Сдал» (`:-1` — устаревшая кнопка, отвечает подсказкой про заявку) |
| `su:<subject_id>` | «Отменить» своё «Сдал» (60 с) |
| `sm:<subject_id>` | «Попросить −1» (дальше — ввод причины) |

**Панель (`admin.py`):**
| Префикс | Значение |
|---|---|
| `adm` | главное меню панели |
| `ar` | заявки (вход и −1) |
| `rq:ok\|no:<chat_id>[:l]` | решение по заявке на вход (`:l` — из списка) |
| `mr:ok\|no:<id заявки>[:l]` | решение по заявке на −1 |
| `ap`, `apa`, `api` | люди; добавить списком; убранные из группы |
| `apg`, `apgl:<1/2>` | подгруппы: сводка; вставить список подгруппы |
| `au:<student_id>` | карточка человека |
| `aun`, `aus:<id>:<0/1/2>`, `aur:<id>:<роль>` | ФИО, подгруппа, роль (`user`/`starosta`/`admin`) |
| `aul`, `aulok` | отвязать Telegram (подтверждение) |
| `aux`, `auxok`, `auv` | убрать из группы (подтверждение), вернуть |
| `aq`, `aqs:<subject_id>`, `aqf:<subject_id>:<0/1/2>`, `aqr:<subject_id>` | сданные: предметы, очередь, фильтр, «Обновить» |
| `aqe:<subject_id>:<student_id>[:p]` | карточка «сданные человека» (`:p` — открыта из карточки человека) |
| `aqd:<subject_id>:<student_id>:<±1>[:p]` | поправить счётчик |
| `aqw:<subject_id>:<student_id>[:p]` | поставить/снять 🙋 |
| `ab`, `abok` | рассылка: текст, отправить |
| `aj`, `ajl:<вкладка>:<стр>`, `ajr:<вкладка>:<стр>`, `ajt` | журнал: открыть, страница, «Обновить» с кулдауном, последняя ошибка целиком. Вкладки: `a` действия, `s` события сервера, `e` предупреждения и ошибки, `x` всё |
| `abk` | копия базы (только админ) |
| `as`, `asw`, `asa`, `asn`, `ast`, `ase`, `asek`, `asx`, `asxok` | предметы: список, карточка, добавить, название, число работ, эмодзи (`asek` — пропустить), удалить |

Сообщения со старыми кнопками (например, после обновления бота) ловит `stale_callback` — открывает меню.

## 9. Журналы и логи

**Два разных журнала в Панели → «Журнал»** (оба — в блоке кода, по 12 записей на странице, новые сверху, даты-разделители):
- **Действия** (`audit`) — кто из старост/админов что сделал. Видят староста и админ.
- **Сервер / Ошибки / Всё** (`server_log`) — всё, что бот пишет через `logging`. Только админ. «Сервер» скрывает
  однотипные «Update … is handled», «Ошибки» — WARNING и выше (с последней строкой traceback), «Всё» — без фильтра;
  кнопка «Последняя ошибка целиком» показывает полный traceback.

`logsink.py`: хендлер `DbLogHandler` на корневом логгере складывает записи в очередь в памяти (в нём нельзя трогать базу:
логи пишутся и из потоков), фоновая `flusher` раз в 2 секунды переносит их в `server_log`; перед показом журнала
вызывается `logsink.flush`. **Токен бота вырезается** из текста и traceback (`logsink.SECRET`).
Те же строки идут и в `journalctl -u queue-bot`.

## 10. Копия базы

Кнопка «💾 Копия базы» (только админ) → `Database.backup_zip()`: `VACUUM INTO` во временный файл (согласованная копия,
пока бот работает) → zip с файлом `queue.db` → отправка документом. Имя: `bd-<GROUP_NO>-дд-мм-гггг-ччмм.zip`, например
`bd-513802-28-10-2026-1250.zip`. В копии ФИО и Telegram ID — персональные данные. Отдельно на сервере раз в сутки
(`queue-bot-backup.timer`) делается копия в `/var/lib/queue-bot/backups` (14 дней).

## 11. Развёртывание (Debian)

```
/opt/queue-bot          код (git-клон; можно стереть и скачать заново)
/etc/queue-bot/env      настройки: BOT_TOKEN, ADMIN_IDS, TIMEZONE (+ GROUP_NO при желании); root, права 600
/var/lib/queue-bot      queue.db и backups/ (владелец queuebot)
/usr/local/bin/queue-bot  → /opt/queue-bot/deploy/queue-bot   (команда управления)
```
Служба `queue-bot.service` (systemd) работает от пользователя `queuebot` без прав root; запись разрешена только в
`/var/lib/queue-bot`. `deploy/install.sh` — установка и повторная установка; `deploy/queue-bot` — `update`, `status`,
`logs`, `restart`, `stop`, `start`, `backup`, `config`; `deploy/common.sh` — общие функции. `queue-bot update`:
`git fetch` → бэкап базы → `git reset --hard` на `origin/<ветка>` → зависимости → перезапуск; если бот не поднялся —
откат на прошлый коммит. Миграции базы выполняются сами при старте бота (раздел 4.3), настройки и база при обновлении
не трогаются. Подробности и команды — в `README.md`.

Переменные окружения (`config.py`): `BOT_TOKEN` (обязательно), `ADMIN_IDS`, `DB_PATH`, `TIMEZONE`, `GROUP_NO`
(только для имени файла копии базы).

## 12. Тесты

`python -m pytest` (нужен только `pytest`; настоящий Telegram и токен не нужны).
- `test_ranking.py` — порядок очереди и **статистическая проверка равномерности жребия**.
- `test_db.py` — база: заявки, очередь, жребий, отмена, −1, подгруппы, миграции со старых баз, копия, логи.
- `test_logsink.py` — логи в базу, скрытие токена. `test_admin_format.py` — оформление журнала, проверка эмодзи.
- `test_scenario.py` — **сквозной сценарий** на поддельном Telegram (`tests/harness.py`): настоящие обработчики, вместо сети
  запись вызовов. Здесь проверяется то, что видит пользователь: тексты, кнопки, уведомления, права.
- `test_docs.py` — документация не отстаёт от кода.

Чтобы проверить новую кнопку, добавь шаги в `test_scenario.py` (или собери короткий сценарий через `Harness`) и убедись, что
проверки названы по смыслу.

## 13. Грабли

- `callback_data` ≤ 64 байта; `message is not modified` — не ошибка (`show()` её глотает); лимит текста Telegram 4096
  символов (журнал режется страницами).
- В `<pre>` Telegram не переносит строки — журнал сам заворачивает строки по `admin.JOURNAL_WIDTH` = 58 символов.
- SQLite `lower()` не понимает кириллицу — сравнения без учёта регистра делай в Python (`casefold`).
- `VACUUM INTO` нельзя внутри открытой транзакции; все записи в `db.py` сразу коммитятся.
- Новые админ-обработчики регистрируй в `admin.py` (он подключён раньше), студенческие — в `handlers.py` **выше**
  запасных обработчиков.
- Список группы и сданные — только в базе, в репозиторий не попадают. Токен бота — только в `/etc/queue-bot/env`.
- aiogram 3: фильтр состояния `AdminForm.x` перед `F.text`; команды (`/…`) внутри ввода игнорируются условием
  `~F.text.startswith("/")`.
