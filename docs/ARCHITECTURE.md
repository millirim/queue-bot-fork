# Устройство бота: движок и база данных

Подробное и точное описание. Короткая версия для быстрого старта — в [`AGENTS.md`](../AGENTS.md).
Если меняешь код, меняй и этот файл: тест `tests/test_docs.py` проверяет, что все таблицы базы,
переменные окружения и callback-кнопки здесь упомянуты.

## 1. Что это

Telegram-бот «живая очередь на сдачу лаб» для **одной учебной группы** (~30 человек). Нет дат, расписания и
отдельных очередей по парам: по каждому **предмету** есть один постоянный список всей группы. Его открывают на паре
и смотрят, кто следующий. Порядок строится по числу сданных работ и отметке «хочу сдать следующее»
(правила — в разделе 5).

- Стек: Python 3.11+ (на сервере 3.13), aiogram 3.31 (long polling, без вебхуков), aiosqlite (SQLite, один файл).
- Один процесс, одна копия на токен. Белый IP и открытые порты не нужны.
- Весь текст для пользователей — на русском, разметка Telegram — HTML (`parse_mode=HTML`), поэтому всё, что
  вставляется в текст из данных, проходит через `common.esc()`.

## 2. Карта файлов

| Файл | Роль |
|---|---|
| `main.py` | Точка входа: логи, база, `Dispatcher`, команды меню, polling. Порядок — раздел 3. |
| `config.py` | Настройки из переменных окружения и начальный список предметов `SUBJECTS`. |
| `db.py` | **Вся работа с SQLite.** Схема, миграции, все запросы, датаклассы (`Student`, `Subject`, `Row`, `Standing`, …). SQL нигде больше не пишется. |
| `metrics.py` | Нагрузка и события в реальном времени для страницы «Live» (только админ): кольцо событий, посекундные счётчики, перцентили, процессор/память/задержка цикла, middleware бота. Раздел 14. |
| `features.py` | Реестр дополнительных функций (обмены, голосования, предложения…) и ролей, для которых их можно включать и выключать (`feature_flags`). |
| `ranking.py` | Чистая функция порядка очереди `order()`, `draw_lot()`, текст правил `RULES`. Без Telegram и базы. |
| `bottom.py` | Роутер нижней кнопки «🏠 На главную» (под полем ввода). Подключён **первым**. |
| `handlers.py` | Роутер студента: регистрация, очередь, «Сдал/Отменить/−1», «Моё», `/start /help /my /cancel`, запасные обработчики. |
| `admin.py` | Роутер Панели Админа (`/admin`) и панели старосты (`/moderator`): заявки, люди, подгруппы, сданные, рассылка, журнал, предметы, копия базы. |
| `common.py` | Общее: права (`is_creator/is_admin/is_staff`), отправка (`show`, `send`, `send_many`, `edit_sent`), форматирование (`esc`, `kb`, `btn`, `queue_text`, `short_name`), команды меню по ролям, кулдаун «Обновить», фильтр подгруппы. |
| `logsink.py` | Серверные логи в таблицу `server_log` (хендлер `logging` + фоновая задача). |
| `web.py` | Веб-панель: aiohttp-приложение в процессе бота, вход по ссылке из бота, JSON-API (раздел 14). |
| `webui/` | Интерфейс веб-панели: `index.html`, `assets/app.js`, `assets/app.css`, `assets/theme.js`, `assets/mark.svg`. |
| `broadcast.py` | Рассылка с форматированием оригинала: копия сообщения из бота (фото, альбомы, разметка) или HTML и картинки из веб-панели. |
| `updater.py` | Обновление бота по кнопке админа: файлы-запросы в папке данных, версия, доставка итога админу (раздел 11). |
| `deploy/` | Установка и обслуживание на сервере (раздел 11). |
| `tests/` | pytest (раздел 12). |

Зависимости импорта (стрелка — «импортирует»): `main → admin, handlers, common, db, logsink, updater, web, config`;
`web → admin, common, db, logsink, updater, ranking, config`;
`handlers → admin (close_notices, notify_*), common, db, ranking`; `admin → common, db, logsink, updater, ranking, config`; `updater → common, config`;
`common → db, ranking, config`; `db → ranking, config`; `logsink → db, config`. Циклов нет (`ranking` и `config`
ни от кого не зависят).

## 3. Запуск (`main.py`)

1. `logging.basicConfig(INFO)` и `logsink.install()` — те же логи пишутся и в базу.
2. Проверка `BOT_TOKEN`; если `CREATOR_IDS` пуст — предупреждение (заявки тогда принимаются автоматически).
3. `Database.connect()` (раздел 4.3), запуск фоновой задачи `logsink.flusher`.
4. `Dispatcher`, `dp["db"] = db` (хендлеры получают `db: Database` аргументом).
5. **Порядок роутеров важен:** сначала `bottom.router` (нажатие нижней кнопки не должно попасть в ввод причины, списка или рассылки), затем `admin.router`, потом `handlers.router` — в конце `handlers.py` стоят
   «запасные» обработчики (`stale_callback`, `fallback_message`), которые ловят всё подряд.
6. Команды меню: всем `BASE_COMMANDS`; админам (`CREATOR_IDS` и назначенным) добавляется `/admin`, старостам `/moderator`
   (`set_commands` с `BotCommandScopeChat`).
7. `web.start(db, bot)` — веб-панель на `WEB_HOST:WEB_PORT` (раздел 14); порт занят — ошибка в лог, бот работает дальше.
8. `start_polling`. При остановке: запись «Бот остановлен», сброс последних логов, закрытие базы.

FSM-состояния (`aiogram` `MemoryStorage`, **сбрасываются при перезапуске**): `handlers.MinusForm.reason`;
`admin.AdminForm`: `name`, `roster`, `subgroup_list`, `broadcast`, `subject_name`, `subject_emoji`, `subject_total`.

## 4. База данных

### 4.1. Общее

SQLite, один файл (`DB_PATH`; на сервере `/var/lib/queue-bot/queue.db`), WAL, `foreign_keys=ON`. Одно соединение
`aiosqlite` на весь процесс (`Database.conn`); каждая запись сразу `commit`. Время — **локальное, без tzinfo**,
строкой ISO (`TIMEZONE`, по умолчанию Europe/Minsk): `db.local_now()`.

### 4.2. Таблицы

**`students`** — список группы. Главная таблица: очередь строится по ней.
| Колонка | Смысл |
|---|---|
| `id` | PK. Все связи идут по нему, а не по Telegram ID. |
| `name` | ФИО полностью, `UNIQUE`. В очереди показывается как «Фамилия И.О.» (`common.short_name`). |
| `active` | 1 — в группе, 0 — убран (например, отчислен). Убранных нет в очередях, данные сохраняются. |
| `chat_id` | Telegram ID привязанного аккаунта, `UNIQUE`; `NULL` — человек ещё не зарегистрировался в боте. |
| `username` | @ник на момент привязки (только для показа админам). |
| `role` | `user` / `starosta` / `admin`. Роль **закреплена за ФИО**: её можно назначить заранее, и она сработает после регистрации; при отвязке Telegram роль остаётся. |
| `subgroup` | 1, 2 или 0 (не указана). **Только фильтр просмотра**, на порядок очереди не влияет. |

**`requests`** — заявки на вход: «этот Telegram — вот этот человек из списка». PK `chat_id` (одна заявка на аккаунт),
`student_id → students ON DELETE CASCADE`, `username`, `created_at`.

**`subjects`** — предметы: `id`, `name` `UNIQUE`, `total` (сколько всего работ), `emoji` (по умолчанию `📚`).
`Subject.title` = «эмодзи название» — так предмет показывается в кнопках и заголовках.

**`progress`** — сколько сдал человек по предмету. Ключ — пара `student_id` + `subject_id` (оба → `students` и
`subjects`, `ON DELETE CASCADE`).
| Колонка | Смысл |
|---|---|
| `done` | Сдано работ, `0…subjects.total`. |
| `want_since` | Время нажатия «Хочу сдать следующее»; `NULL` — не хочет. Используется только как флаг «хочет». |
| `lot` | **Устарела**, не используется (жребий теперь в `lots`); колонка осталась ради старых баз. |
| `undo_until` / `undo_want` | До какого времени можно отменить своё «Сдал» (60 с) и какая отметка «хочу сдать» была до него. |

Строки `progress` создаются лениво (`_ensure_progress`); нет строки — значит `done = 0`, не хочет.

**`lots`** — жребий. Колонки `student_id`, `subject_id`, `work` (номер работы, `done + 1`), `day` (местная дата),
`lot` (само число); PK — первые четыре, то есть **одно число на человека, предмет, номер работы и день**. Создаётся при первом показе очереди, когда человек «хочет» (`Database._lots`,
`INSERT OR IGNORE`), поэтому никакие нажатия его не меняют. Записи прошлых дней удаляются — в полночь у всех
новый жребий. `lot` — случайное число от 0 до 2⁶²−1 (`ranking.draw_lot`, `random.SystemRandom`).

**`minus_requests`** — заявки «уменьшить сданные на 1» с причиной: `id`, `student_id`, `subject_id`, `reason`,
`created_at`, `UNIQUE (student_id, subject_id)` (новая заявка заменяет старую).

**`request_notices`** — какие сообщения с кнопками бот отправил проверяющим, чтобы после решения у всех заменить
их на итог без кнопок. `applicant` — `chat_id` подавшего заявку (для `kind='reg'`) или `id` заявки на −1
(`kind='minus'`); `reviewer` — кому отправлено; `message_id`; `kind`.

**`audit`** — журнал действий старост и админов: `id`, `at`, `actor_id`, `actor_name` (в виде «админ Иванов Иван»),
`text` (чистый текст, без HTML). Пишется `Database.log_action` через `admin.journal_add`. Не очищается.

**`server_log`** — серверные логи: `id`, `at`, `level`, `logger`, `message`, `trace` (traceback, если был). Хранятся
последние `db.LOG_KEEP` = 5000 строк (лишние удаляются при каждой записи).

**`web_sessions`** — входы в веб-панель (`web.py`). `token` — **sha256** токена (сам токен есть только в ссылке или
в cookie браузера), `chat_id` — чей Telegram, `kind` — `login` (одноразовая ссылка из бота, 10 минут) или `session`
(вход в браузере, 30 дней), `created_at` и `expires_at` — местное время ISO. Просроченные строки удаляются при каждой
проверке (`Database.web_check`). Отвязка Telegram, «убрать из группы» и роль, которой веб закрыт, завершают сессии
человека (`web_logout`).

**`metrics_minute`** — нагрузка по минутам для графика «последний час»: `minute` PK (ISO до минуты), `requests`, `errors` (5xx), `updates`
(обновлений бота), `log_errors`, `p50`, `p95` (мс), `cpu` (%), `rss_mb`, `lag_ms` (опоздание цикла событий). Пишет `metrics.collector`
раз в минуту, хранится `Database.METRICS_KEEP_DAYS` = 7 дней.

**`activity`** — когда человек последний раз был в вебе и в боте: `chat_id` PK, `web_at`, `bot_at` (ISO, местное время). Пишется через
`Database.touch(chat_id, 'web'|'bot')`, не чаще раза в `db.TOUCH_EVERY` = 20 с на человека. «Онлайн» — сигнал вебу не старше
`db.ONLINE_SECONDS` = 60 с (страница шлёт `POST /api/presence` раз в 20 с, пока вкладка видна, плюс любое действие в панели);
в боте отмечает любое обновление (`common.ActivityMiddleware`). Показывается только тем, кому включена функция `presence`
(по умолчанию — старостам и админам): зелёная точка в очереди, списке людей и карточке, «веб: … · бот: …».

**`feature_flags`** — видимость дополнительных функций по ролям: PK (`feature`, `role`), `enabled`. Функции перечислены в
`features.FEATURES`, роли — `user`/`starosta`/`admin`; нет строки — значение по умолчанию (включено). Создатель видит всё
всегда. Меняет админ: бот «Панель Админа → ⚙️ Функции» (`fx`, `fx:<функция>:<роль>`) и веб «Сервер → Функции по ролям».

**`swaps`** — обмен местами по предмету. `id`, `subject_id`, `from_id` (кто предложил), `to_id`, `status`: `pending` (предложение,
живёт `db.SWAP_ASK_HOURS` = 24 ч), `active` (действует), `used` (закончился: кто-то сдал или поправили счётчик),
`cancelled`/`declined` (отменён, отозван, отказ, человека убрали из группы). `work_from`/`work_to` — какую по счёту работу
(`сдано + 1`) сдавал каждый, когда согласились; `created_at`, `ended_at`, `ended_by` (кто сдал — чтобы «Отменить Сдал»
в течение минуты вернул обмен). Правила — раздел 5; лимит и жизненный цикл — `Database.swap_blocked/propose_swap/accept_swap/
end_swap/_end_swaps`.

**`polls`** — голосования (создаёт и закрывает только админ): `id`, `question`, `created_at`, `created_by` (подпись админа),
`closed_at` (`NULL` — открыто). Голосование анонимное: админ видит только цифры и тех, кто ещё не голосовал
(`Database.poll_nonvoters`), но не выбор каждого. Удаление голосования каскадом чистит варианты и голоса.

**`poll_options`** — варианты ответа: `id`, `poll_id`, `pos` (порядок показа), `text`.

**`poll_votes`** — голоса: PK (`poll_id`, `student_id`) — один голос на человека; `option_id` — выбранный вариант, `voted_at` —
когда. Пока голосование открыто, голос можно поменять (`Database.vote` возвращает `ok`/`same`/`closed`/`none`); голоса
ушедших из группы в итог не входят.

**`suggestions`** — предложения из веб-панели. `id`, `author_id` (→ `students`; **`NULL` — анонимно**: автор не
записывается вообще), `anonymous`, `public` (1 — видно всей группе и его можно поддержать, 0 — только старостам и
админам), `text`, `created_at`, `status` (`new` / `accepted` / `done` / `rejected`), ответ проверяющего — `reply`,
`reply_by` (подпись), `reply_at`.

**`suggestion_votes`** — «Поддерживаю» под предложением: `suggestion_id`, `student_id`, один голос на человека.

**`meta`** — разовые миграции данных: `key`/`value`. Сейчас один ключ `subjects-v2` (прежние названия БЖЧ →
БЖЧ-ЛР/БЖЧ-ПЗ и эмодзи по умолчанию; выполняется ровно один раз на базу).

### 4.3. Создание и миграции (`Database.connect`)

1. `PRAGMA journal_mode=WAL`.
2. `_drop_old_schema` — **только для очень старых баз** (`PRAGMA user_version` меньше `SCHEMA_VERSION`, и есть таблицы
   прошлых поколений): пересоздаёт всё. Сейчас `SCHEMA_VERSION = 4`.
   **Не увеличивай `SCHEMA_VERSION`, не написав миграцию данных: при несовпадении база будет стёрта.**
3. `PRAGMA foreign_keys=ON`, `executescript(SCHEMA)` — `CREATE TABLE IF NOT EXISTS` для всех таблиц.
4. `_add_new_columns` — **так добавляются новые колонки в существующие базы**: `_add_column(table, column, ddl)`
   делает `ALTER TABLE ADD COLUMN`, если колонки ещё нет. Данные не затрагиваются. Затем `_migrate_subjects`.
5. `_seed_subjects` — если таблица `subjects` пуста, заполняет её из `config.SUBJECTS` (название → (число работ, эмодзи)).

Правило для будущих изменений: новая колонка = строка в `SCHEMA` **и** строка в `_add_new_columns`; новая таблица =
только в `SCHEMA`; разовое преобразование данных = ключ в `meta`.

- Заявки на вход: `create_request`, `get_request`, `pending_requests`, `link`, `approve`, `reject`,

- Очередь: `queue(subject_id)` → список `ranking.Row` в порядке очереди; `standing` (место в общей очереди и в подгруппе),

## 5. Порядок очереди (`ranking.py`)

`db.queue()` собирает по `students` (только `active = 1`) строки `Row(student_id, name, done, wants, lot, in_bot, subgroup)`
и сортирует `ranking.order()` по ключу:

1. **Желающие** (`wants`) выше всех остальных.
2. Среди **не желающих** — те, кто **ещё не в боте** (`in_bot = False`, нет `chat_id`), в самом низу, без приоритета.
   (Если староста поставил такому 🙋 — он среди желающих.)
3. Меньше `done` — выше.
4. Среди желающих при равном `done` — меньший `lot` (жребий).
5. По алфавиту (`casefold`).

Подгруппы порядок не меняют: фильтр «Все / 1 подгр. / 2 подгр.» только скрывает чужую подгруппу при показе
(`common.queue_text(..., subgroup=N)`; номера считаются внутри выбранной). Выбор фильтра запоминается на человека в
памяти (`common.subgroup_view`) до перезапуска.

Жребий (раздел 4.2, `lots`) даёт каждому из равных одинаковый шанс на любое место; перебросить его нельзя ни «опустить
и поднять руку», ни «Сдал» → «Отменить». В полночь у всех новый. Равномерность проверена в `tests/test_ranking.py`.

**Обмен местами** (таблица `swaps`, `ranking.apply_swaps` после `order`): двое по обоюдному согласию меняются местами
по предмету, сколько бы у кого ни было сдано. Правила, которые не дают этим пользоваться во вред:
- **места третьих не меняются** — меняются ровно две строки; у человека не больше одного обмена на предмет, цепочек нет;
- обмен **«спит»**, пока двое не в одном блоке очереди (оба с 🙋 или оба без, оба в боте), — блоки не перемешиваются, но
  договориться можно заранее;
- обмен **временный**: заканчивается (`used`), когда у кого-то из двоих меняется число сданных (его «Сдал», правка старосты,
  откат); оба сразу на своих обычных местах; второму приходит сообщение (`db.on_swap_ended` → `handlers.swap_ended`);
  «Отменить Сдал» в течение минуты возвращает обмен; любой из двоих и админ могут отменить его в любой момент;
- **лимит — один обмен на каждую работу**: пока обмен на работе №n был (`active` или `used`), следующий у этого человека
  возможен только на n+1. Откат n+1 → n лимит не возвращает: запись о работе №n остаётся навсегда. Отменённый обмен
  (`cancelled`/`declined`/просрочка) лимит не тратит. При запуске у всех истории нет — меняться можно сразу;
- нужно согласие второго (предложение живёт сутки); в очереди пара помечена 🔁, действия админа — в журнале.

**Нельзя выгодно уменьшить свой счётчик** — меньше сдано значит выше в очереди. Поэтому:
- «✅ Сдал» (+1) доступен всем себе; кнопка «↩️ Отменить» живёт `db.UNDO_SECONDS` = 60 с и возвращает всё как было;
- «−1» себе — только через заявку («🙏 Попросить −1» с причиной), её одобряет другой староста или админ;
  свою заявку решить нельзя; староста/админ себе «−1» напрямую тоже не ставит (`cb_progress_change`);
- староста и админ правят сданные **другим** сразу (с записью в журнал и уведомлением человеку).

## 6. Роли и права

| Роль | Откуда | Что может |
|---|---|---|
| студент (`user`) | по умолчанию | очередь, 🙋, «Сдал», «Отменить», «Попросить −1», «Моё» |
| староста (`starosta`) | `students.role` | + `/moderator`: заявки, ФИО, сданные и 🙋 за других, рассылка, журнал действий |
| админ (`admin`) | `students.role` | + `/admin`: список группы, подгруппы, роли, отвязка Telegram, убрать/вернуть, предметы, серверные логи, копия базы |
| создатель 👑 | `config.CREATOR_IDS` (раньше `ADMIN_IDS` — читается тоже) | как админ, **плюс** его нельзя снять из бота; может работать, даже не выбрав себя из списка |

Функции (`common.py`): `is_creator(chat_id)` — в `CREATOR_IDS`; `is_admin(chat_id, student)` — создатель или `student.admin`;
`is_staff` — админ или староста; `staff_kind` → `'admin'` / `'moderator'` / `None`; `panel_name(kind)` — «Панель Админа»
или «Панель старосты». В `admin.py` каждый обработчик начинается с `need_staff(target, db, admin_only=False)`;
`admin_only=True` пускает только админов. Проверка прав всегда на сервере, прятать кнопку недостаточно.

Значки в списке людей: ✅ студент · ✴️ староста · ♒️ админ · ❌ не зарегистрирован (❌✴️ — роль назначена заранее).

## 7. Основные сценарии

**Регистрация.** `/start` без привязки → `show_roster` (свободные имена, `students.chat_id IS NULL`) → «Это я» →
`create_request` + `notify_reviewers` (всем из `CREATOR_IDS` и `staff_chats()`; сообщения запоминаются в `request_notices`).
Проверяющий жмёт ✅/❌ → `db.approve`/`reject` → `close_notices` меняет сообщение у **всех** проверяющих на итог без кнопок.
Одно имя — один аккаунт (`link` отказывает, если имя уже занято). Если `ADMIN_IDS` пуст или пишет главный админ —
привязка сразу, без заявки. Если имя с ролью — проверяющего предупреждают.

**«Сдал».** `mark_done` → `change_done(+1)`: счётчик +1, отметка 🙋 снимается; запоминает `undo_until` и прежний `want_since`.
`undo_done` в течение минуты возвращает счётчик и отметку.

**«−1» по заявке.** `sm:` → FSM `MinusForm.reason` → `create_minus` → `notify_minus` (всем проверяющим, кроме просящего) →
`mr:ok|no` → `change_done(−1)`, ответ человеку, запись в журнал, `close_notices(kind='minus')`.

**«Обновить».** `common.refresh_wait(chat_id)` — 3 секунды на человека (память процесса); в тексте — время обновления.
`show()` терпит `message is not modified` и `TelegramRetryAfter`.

**Команды меню** (`common.set_commands`) пересоздаются при смене роли, принятии заявки, отвязке, возврате/удалении из группы
и при старте бота.

## 8. Кнопки (`callback_data`)

`chat_id` (где указано). Все обработчики ловятся в `handlers.py` (студент) и `admin.py` (панели); у `admin.py`
приоритет.

| `aul`, `aulok` | отвязать Telegram (подтверждение) |

**Кнопка под полем ввода** (`common.bottom_menu`, `bottom_for`; обработка — `bottom.py`) — одна постоянная красная
«🏠 На главную» (`ReplyKeyboardMarkup`, `is_persistent`). Нажатие приходит боту **обычным текстом**: `bottom.py` сбрасывает
начатое действие, удаляет это сообщение и открывает главное меню (inline). Все остальные кнопки — под сообщениями бота.
Клавиатуру можно выставить только вместе с сообщением бота, поэтому её присылают `/start`, регистрация, принятие заявки,
смена роли и возврат/исключение из группы (там — `ReplyKeyboardRemove`); устаревшую подменяет `fallback_message`.

**Цвет кнопок** (Bot API 9.4, поле `style`: `danger` красная, `success` зелёная, `primary` синяя): `common.btn(text, data, style=None)`.
Сейчас цветная одна кнопка — «🏠 На главную» (`common.MENU_BTN`, красная, `callback_data="menu"`), она стоит на всех экранах
кроме самого главного меню. aiogram 3.31 поле `style` поддерживает; старые клиенты Telegram рисуют такую кнопку обычной.

## 9. Журналы и логи

**Два разных журнала в Панели → «Журнал»** (оба — в блоке кода, по 12 записей на странице, новые сверху, даты-разделители):
- **Действия** (`audit`) — кто из старост/админов что сделал. Видят староста и админ.
- **Сервер / Ошибки / Всё** (`server_log`) — всё, что бот пишет через `logging`. Только админ. «Сервер» скрывает
  однотипные «Update … is handled», «Ошибки» — WARNING и выше (с последней строкой traceback), «Всё» — без фильтра;
  кнопка «Последняя ошибка целиком» показывает полный traceback.

`logsink.py`: хендлер `DbLogHandler` на корневом логгере складывает записи в очередь в памяти (в нём нельзя трогать базу:
логи пишутся и из потоков), фоновая `flusher` раз в 2 секунды переносит их в `server_log`; перед показом журнала
вызывается `logsink.flush`. **Токен бота вырезается** из текста и traceback (`logsink.SECRET`).
Те же строки идут и в `journalctl -u queue-bot`.

## 10. Копия базы

Кнопка «💾 Копия базы» (только админ) → `Database.backup_zip()`: `VACUUM INTO` во временный файл (согласованная копия,
пока бот работает) → zip с файлом `queue.db` → отправка документом. Имя: `bd-<GROUP_NO>-дд-мм-гггг-ччмм.zip`, например
`bd-513802-28-10-2026-1250.zip`. В копии ФИО и Telegram ID — персональные данные. Отдельно на сервере раз в сутки
(`queue-bot-backup.timer`) делается копия в `/var/lib/queue-bot/backups` (14 дней).

## 11. Развёртывание (Debian)

```
/opt/queue-bot          код (git-клон; можно стереть и скачать заново)
/etc/queue-bot/env      настройки: BOT_TOKEN, CREATOR_IDS, TIMEZONE (+ GROUP_NO при желании); root, права 600
/var/lib/queue-bot      queue.db и backups/ (владелец queuebot)
/usr/local/bin/queue-bot  → /opt/queue-bot/deploy/queue-bot   (команда управления)
```
Служба `queue-bot.service` (systemd) работает от пользователя `queuebot` без прав root; запись разрешена только в
`/var/lib/queue-bot`. `deploy/install.sh` — установка и повторная установка; `deploy/queue-bot` — `update`, `status`,
`logs`, `restart`, `stop`, `start`, `backup`, `config`; `deploy/common.sh` — общие функции. Службы: `queue-bot.service`, `queue-bot-backup.service/.timer`,
`queue-bot-update.service/.path`. `queue-bot update`:
`git fetch` → бэкап базы → `git reset --hard` на `origin/<ветка>` → зависимости → перезапуск; если бот не поднялся —
откат на прошлый коммит. Миграции базы выполняются сами при старте бота (раздел 4.3), настройки и база при обновлении
не трогаются. Подробности и команды — в `README.md`.

**Обновление по кнопке** («🔄 Обновить бота» в Панели Админа, только админ). Бот работает без прав root и себя не обновляет —
он только оставляет запрос, остальное делает systemd от root:
1. `updater.request(chat_id)` атомарно создаёт `/var/lib/queue-bot/update-request` (`{"chat_id": …}`);
2. `queue-bot-update.path` (`PathExists`) запускает `queue-bot-update.service` → `flock` → `queue-bot update-from-bot`;
3. `update_from_bot` (в `deploy/queue-bot`) читает из запроса **только число** `chat_id`, удаляет запрос, ставит
   `update-running` и вызывает ту же `update()` (бэкап → обновление → откат, если бот не поднялся), затем пишет
   `update-result` (JSON: `status` = `ok`/`same`/`failed`, `version`, `old_version`, `changes`, `tail`, `chat_id`);
4. `updater.deliver_results` (фоновая задача бота, опрос каждые 3 с, в том числе сразу после перезапуска) отправляет
   итог админу и удаляет файл. Файл `version` (`write_version` в `deploy/common.sh`) показывается в экране обновления.
Бот ничего не исполняет сам; худшее, что может сделать запрос, — обновить бота до того, что лежит в настроенном репозитории.
**Дежурный ответчик** (`deploy/maintenance.py`, служба `queue-bot-maint`). Пока бот остановлен (перезапуск при обновлении, падение,
загрузка сервера), на любое личное сообщение приходит «🔧 Бот перезапускается, подожди пару минут», а кнопки получают такое же
всплывающее сообщение. Только стандартная библиотека Python — работает, даже если окружение бота сломано. Передача эстафеты без
общего состояния: основной бот при остановке запускает дежурного (`ExecStopPost` в `queue-bot.service`), а когда бот снова опрашивает
Telegram, дежурный получает `409 Conflict` (читать обновления может только один) и тихо завершается. Прочитанное дежурным
подтверждается, поэтому эти сообщения до основного бота не доходят; одному человеку отвечает не чаще раза в 30 с. `queue-bot stop`
останавливает и дежурного. Не поможет, когда сервер выключен или нет сети: отвечать некому. Тесты — `tests/test_maintenance.py`.

Кнопка работает, только если установлен `/etc/systemd/system/queue-bot-update.path` (его ставят `install.sh` и `apply_code`).
Сервер, поставленный **до** этой функции, включает её двумя запусками `sudo queue-bot update`: первый (старая команда)
приносит код, второй (новая) через `apply_code` ставит службы и `version` — `update` вызывает `apply_code` и когда
обновлять нечего. Экран кнопки сам подсказывает это, пока служб нет.

Переменные окружения (`config.py`): `BOT_TOKEN` (обязательно), `CREATOR_IDS` (и старое имя `ADMIN_IDS`), `DB_PATH`, `TIMEZONE`, `GROUP_NO`
(только для имени файла копии базы), `WEB_PORT`, `WEB_HOST`, `WEB_URL`, `WEB_ROLES` (веб-панель, раздел 14).

## 13. Грабли

- `callback_data` ≤ 64 байта; `message is not modified` — не ошибка (`show()` её глотает); лимит текста Telegram 4096
  символов (журнал режется страницами).
- В `<pre>` Telegram не переносит строки — журнал сам заворачивает строки по `admin.JOURNAL_WIDTH` = 58 символов.
- SQLite `lower()` не понимает кириллицу — сравнения без учёта регистра делай в Python (`casefold`).
- `VACUUM INTO` нельзя внутри открытой транзакции; все записи в `db.py` сразу коммитятся.
- Новые админ-обработчики регистрируй в `admin.py` (он подключён раньше), студенческие — в `handlers.py` **выше**
  запасных обработчиков.
- Список группы и сданные — только в базе, в репозиторий не попадают. Токен бота — только в `/etc/queue-bot/env`.
- aiogram 3: фильтр состояния `AdminForm.x` перед `F.text`; команды (`/…`) внутри ввода игнорируются условием
  `~F.text.startswith("/")`.

## 14. Веб-панель (`web.py`, `webui/`)

Тот же бот в браузере: обзор, очереди (с обменом местами), «Моё», голосования, предложения, правила, заявки, люди, рассылка, журнал, предметы, сервер. Работает **в процессе
бота** (aiohttp уже есть в зависимостях aiogram), с той же `Database` и тем же `Bot` — поэтому действия из веба
присылают людям те же уведомления в Telegram и закрывают кнопки заявок у проверяющих (`close_notices`).

**Вход.** Пароля нет. `/web` или «🌐 Веб-панель» (`aw`) в панели → `admin.send_web_link` проверяет роль
(`common.web_role` → `web_allowed`: `WEB_PORT` не 0 и роль в `WEB_ROLES`) и присылает ссылку `WEB_URL/login?t=<токен>`
(`web_sessions.kind='login'`, 10 минут, без превью). Страница `/login` **не** входит сама: вход — POST `/api/login`
по кнопке, чтобы превью ссылок и сканеры не потратили одноразовый токен. Ответ ставит cookie `qb_session`
(`HttpOnly`, `SameSite=Strict`, `Secure` при `https` в `WEB_URL`, 30 дней).

**Мини-приложение Telegram.** При `https` в `WEB_URL` бот шлёт кнопку `web_app` («📱 Открыть в Telegram», `admin.web_app_button`)
и ставит тем, кому разрешена панель, кнопку меню чата «Панель» (`common.set_menu_button`, вызывается из `set_commands`).
Telegram открывает адрес с `#tgWebAppData=<initData>`; `app.js` забирает её из адреса, убирает хэш и шлёт POST `/api/login`
с `{"initData": …}`. `web.init_data_user` проверяет подпись (HMAC-SHA256, ключ `HMAC("WebAppData", BOT_TOKEN)`) и свежесть
`auth_date` (сутки), берёт `user.id`, дальше те же проверки роли и та же cookie. SDK `telegram.org` не подключается
(CSP `script-src 'self'`): нужные события (`web_app_ready/expand`, запрет закрытия свайпом) страница шлёт сама через
`TelegramWebviewProxy`. В Telegram Web (iframe) не работает: `frame-ancestors 'none'` и cookie `SameSite=Strict`.

**Голосования в вебе.** Раздел «Голосования» (`/api/polls…`): админ создаёт (вопрос и 2–8 вариантов), напоминает не голосовавшим,
закрывает и удаляет; все, кого пускают в веб и кто есть в списке группы, голосуют и меняют голос, пока открыто. Логика общая с
ботом — функции `admin.publish_poll`, `remind_poll`, `finish_poll`, `remove_poll` (рассылка в Telegram, итоги, журнал с пометкой
«· веб»). Цифры видит админ, проголосовавший и все — когда голосование закрыто; кто за что — не видит никто, список не
голосовавших — только админ (`web.poll_json`).

**Live: нагрузка и события** (`metrics.py`, страница «Live», только админ). Всё живёт в памяти процесса: кольцо из `EVENT_KEEP` = 1500
событий четырёх видов — `web` (запрос: метод, путь, статус, мс, кто, номер `rid`), `bot` (обновление: команда/кнопка, мс; текст
сообщений людей **не** пишется), `log` (строки логов, `FeedHandler`; у строк, написанных во время запроса, тот же `rid`) и `action`
(запись в журнал действий, `Database.log_action`). Рядом посекундные счётчики за 10 минут, перцентили (`percentile`, ближайший ранг),
процессор процесса, память, `load1`, опоздание цикла событий и размер базы. `GET /api/live` — WebSocket (только админ; проверяется
`Origin`): сразу «hello» (последние 200 событий, 300 точек графика), потом «event» на каждое событие и «tick» раз в секунду;
у каждой подписки очередь на 500 событий — медленная вкладка пропускает, но сервер не тормозит. `GET /api/metrics?minutes=N` —
сводка по минутам из `metrics_minute`. Пинг страницы (`/api/ping`) и сам поток в счётчики и ленту не идут, фоновые запросы
(`/api/presence`, `/api/badges`, …) помечены `noise` и по умолчанию скрыты. Номер запроса приходит и заголовком `X-Request-Id`;
необработанная ошибка в веб-запросе возвращается как 500 «Внутренняя ошибка сервера» и пишется в лог. Страница: плитки, схема
«Telegram → бот → база ← веб ← браузеры» со вспышками, два графика, лента с фильтрами и «все события одного запроса».
Тесты — `tests/test_metrics.py`.

**Видимость функций.** Дополнительные функции (`features.FEATURES`: обмены, голосования, предложения) включаются по ролям. Проверка —
на сервере: в боте `common.feature_allowed`, в вебе `web.need(..., feature=...)` / `need_student(..., feature=...)` → 403 «Эта функция для
тебя выключена»; `/api/me` отдаёт `features`, по ним интерфейс прячет пункты меню. Создатель обходит выключатель (в режиме
«смотреть как студент» видит как студент). Рассылки голосований идут только тем, у кого функция включена
(`Database.feature_chats`). Выключение обмена не разрывает действующие обмены — их разрывает админ.

**Цветные ники.** `app.js: nick(name, {role, creator})`: староста — зелёный, админ — фиолетовый, создатель — градиентная рамка и
шрифт Exo 2 (`webui/assets/fonts`, SIL OFL; подключается только для ника). Очередь отдаёт `role`/`creator` в строках.

**Права** — на каждом запросе заново (`web.viewer` → `need(request, 'user'|'starosta'|'admin')`), как `need_staff`
в `admin.py`: роль сняли в боте — следующий запрос получит 403. Студенческие действия (`need_student`) — только тому,
кто есть в списке группы. Заголовок `X-View-As` позволяет админу посмотреть панель глазами старосты или студента —
права **только понижаются**; подпись в журнале остаётся по настоящей роли.

**Защита.** POST/DELETE без заголовка `X-Queue-Bot: 1` отклоняются (чужой сайт не может его поставить без CORS — это
защита от CSRF вместе с `SameSite=Strict`). Ответы: строгая CSP (`script-src 'self'`, без inline), `frame-ancestors
'none'`, `nosniff`, `no-referrer`; API — `Cache-Control: no-store`. Тело запроса — до 256 КБ. Журнал доступа aiohttp
выключен (каждый пинг в `server_log` не нужен). В `app.js` данные вставляются только как текст (функция `h()`).

**API** (`/api/…`, JSON; ошибки — `{"error": текст}` с кодом 400/401/403/404/409):
| Путь | Кому | Что |
|---|---|---|
| `GET ping` | всем | время сервера (мс), смещение пояса, аптайм — для пинга и часов |
| `POST login`, `POST logout` (`everywhere`) | — | вход по токену, выход (везде) |
| `GET me`, `GET overview`, `GET subjects` | роль | кто я и доступные виды; обзор; предметы |
| `GET queue/<id>`, `POST queue/<id>/want\|done\|undo\|minus` | студент из списка | очередь и свои кнопки (как `sw`, `sd`, `su`, `sm`) |
| `GET my` | студент из списка | «Моё»: сданные, места, обмены, свои заявки на −1 |
| `GET queue/<id>/swap`, `POST queue/<id>/swap` (`to`), `POST swaps/<id>/accept\|end` | студент из списка | обмен местами: с кем можно, предложить, принять, отказаться/отозвать/отменить (как `sx`, `sxp`, `sxy`, `sxn`, `sxc`) |
| `GET suggestions`, `POST suggestions` (`text`, `anonymous`, `public`), `POST suggestions/<id>/vote`, `DELETE suggestions/<id>` | роль (поддержать — студент; удалить — автор или админ) | предложения |
| `POST suggestions/<id>/answer` (`status`, `reply`) | староста | ответ и статус предложения, автору — уведомление |
| `GET badges` | роль | счётчики меню: заявки, новые предложения, входящие обмены, неотвеченные голосования |
| `GET requests`, `POST requests/reg/<chat_id>`, `POST requests/minus/<id>` | староста | заявки (как `rq`, `mr`) |
| `GET people[?inactive=1]`, `GET people/<id>`, `POST people/<id>/name\|subgroup` | староста | люди, карточка, ФИО, подгруппа |
| `POST people`, `POST people/<id>/role\|unlink\|active`, `POST subgroups` | админ | список, роль, отвязка, убрать/вернуть, подгруппы списком |
| `POST progress/<subject>/<student>` (`delta` ±1 или `want`) | староста | правка сданных и 🙋 (как `aqd`, `aqw`; себе −1 нельзя) |
| `GET/POST broadcast` (multipart: `html`, `photo` ×10, `test`), `GET journal?tab=a\|s\|e\|x&page=`, `GET journal/trace` | староста (s/e/x, trace — админ) | рассылка (HTML чистит `broadcast.clean_html`; `test` — только себе), журнал |
| `POST subjects`, `POST/DELETE subjects/<id>`, `GET server`, `POST server/update\|backup` | админ | предметы, сервер, обновление, копия базы |

**Предложения.** Пишет любой, кому открыт веб: подписанно или анонимно, всей группе (`public`, можно поддержать) или
только старостам и админам. Анонимное сохраняется **без автора** (`author_id = NULL`), в журнал и логи автор не попадает;
ограничение «5 в сутки» считается в памяти процесса, а не в базе. Старостам и админам — уведомление в Telegram; ответ
и статус (`new` / `accepted` / `done` / `rejected`) — подписанному автору в Telegram.

**Рассылка** (`broadcast.py`). Из бота сообщение не пересказывается, а копируется (`copy_message`, для альбома —
`copy_messages`): сохраняются разметка, картинки, файлы, альбомы. Подпись «📢 Сообщение (…)» ставится в начало текста
или подписи; где для неё нет места (стикер, кружок, альбом, длинный текст) — отдельным сообщением перед оригиналом.
Части альбома собираются `broadcast.ALBUM_WAIT` секунд, предпросмотр — настоящая копия себе. Из веба — HTML редактора
(только теги Telegram: `b i u s code pre a blockquote tg-spoiler`) и до 10 картинок JPEG/PNG/WebP по 10 МБ: первому
получателю файл загружается, остальным уходит `file_id`.

**Интерфейс** (`webui/`) — одна страница без сборки и внешних библиотек: маршруты в `#/…`, данные обновляются сами
(очередь — раз в 5 с). Стиль — как у сайтов Cloudflare 2026: линии с квадратными «узлами» на углах (`.nodes`, `.grid.joined`),
капсульные кнопки, моноширинные ярлыки (`.tag`, `.label`), пунктирные разделители, точечная сетка по краям. Ширины:
от 1600 px — широкий ПК; до 900 px — вместо бокового меню нижние вкладки (`TABS` в `app.js`, остальное в «Ещё»), пинг и время
сервера — капсулой в шапке; до 640 px таблицы (`rt()`) становятся карточками, окна выезжают снизу; до 380 px — узкие
телефоны. Горизонтальной прокрутки нет ни на одной странице. Строка состояния внизу (на ПК): пинг до `/api/ping` раз в 2 с (по клику — минимум, среднее,
95-й процентиль, джиттер, потери), время сервера до миллисекунд (смещение часов считается как в NTP по замеру с
наименьшим пингом), аптайм, версия. Темы: «как в системе», светлая, тёмная, AMOLED — цвета нейтрально-серые,
переменные в `:root` (`app.css`), выбор хранится в `localStorage` и ставится до отрисовки (`theme.js`).

**Наружу** панель выпускают только через HTTPS (обратный прокси или Cloudflare Tunnel до `127.0.0.1:WEB_PORT`), в
`WEB_URL` — публичный адрес. По умолчанию вход всем из списка группы (`WEB_ROLES=admin,starosta,user`).
